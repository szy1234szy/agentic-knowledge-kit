# FEAT-KIT-IMPACT-EVIDENCE 从验证证据反查受影响资产

## 需求与设计

测试文件变更时，impact 能找到直接登记的证据和相连的功能计划。通过 verified_by 使用相同证据的架构、约束和故障记录也应进入待复核清单。约束见 [从证据变更找当前使用方](invariants.md#从证据变更找当前使用方)。

沿已经直接命中的证据记录反查一层现行资料。这使证据变更可以找到使用它的资产，查找范围由登记的验证关系限定。普通关联继续按原有计划提示规则处理。

## 验收

- 单独改动证据路径，可查到使用该证据的当前约束和功能。
- 关联类型为 related_to 的普通文档、已归档和已废弃的记录无需进入影响清单。
- 直接范围匹配和已有的关联计划提示继续有效。

## 交付结果

三项验收通过。实现后用自用索引反查工具与测试的影响，更新架构、能力边界、审计约束和证据记录。安装、质量和维护资料通过单独的入口定位，安装测试路径不再误报原审计计划和编码故障。详见 [实测记录](verification-impact.md)。

基于 `97465b8` 的文档维护复跑了原反查回归，并验证发布脚本及规范接入 Skill 可定位到各自的工程手册章节。现有证据反查规则继续适用。

在套件根目录运行以下命令，预期看到安装与发布章节，以及安装知识边界。共用测试文件只确定待复核候选，具体变更仍须核对 Diff。

~~~powershell
python scripts/knowledge.py --registry docs/self/registry.json impact scripts/test_install.py
~~~
