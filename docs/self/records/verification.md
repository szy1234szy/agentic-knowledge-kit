# EVID-KIT-SELF-001 自用首轮实测

## 执行记录

1. 开发前登记功能为提案并运行 context，找回现有能力、ADR 和不变量。架构记录提供工具入口，审计约束要求单份资料出现问题时其余结果仍可输出。
2. 用 v0.11 与新实现复跑同一组资料。旧版因非法 UTF-8 返回 2，新版报告问题文件并完成其余文件的查重。带类型筛选的架构复核只显示已登记的该类型资产。
3. 实现后运行 impact，从工具与测试路径反查能力说明、架构、约束、功能计划和故障记录，再更新状态及证据。运行严格索引校验和链接审计。
4. 从发布包解压并安装到临时目标。目标获得空白索引，发布包中的自用记录保留在套件目录。后续项目可用同样的隔离方式验证是否能维护自己的资料。

## 回归入口

- 按类型限制检索和正文读取。 [工具测试](../../../scripts/test_knowledge.py)
- 旧编码 Markdown 只报告一次，其他可读文档继续查重。 [工具测试](../../../scripts/test_knowledge.py)
- 新安装保留项目索引边界。 [安装测试](../../../scripts/test_install.py)

## v0.19 文档维护模式走查

在查看新版结果前，固定四问和判据。比较 v0.18 包中的工程手册与增量优化后的同一份手册。

| 读者问题 | v0.18 | v0.19 |
| --- | --- | --- |
| 从哪个目录安装、在哪里验收，成功时看到什么？ | 有两处工作目录、命令和输出 | 保留 |
| 这次只复核了安装资料，怎么留下记录并严格检查？ | 有做法，仍需拼接命令和填写项目 ID | 有实际 ID、JSON 和完整命令 |
| 如何只审查、增量优化或指定重写？默认是哪种？ | 手册未列出 | 三种指令和默认方式可直接找到 |
| 严格同步检查通过后，为什么仍要逐节确认？ | 已说明按文件判断的边界 | 保留 |

按相同判据从 2/4 到 4/4。只审查走查时比较了文档字节。增量改动保留手册原有行和全部 21 个知识 ID。在临时副本指定重写「接入编程规范」一节，检查相邻章节、原有待确认说明和索引保留。另在临时 Git 仓库复跑新示例，补入复核说明前严格检查退出为 1，补入后通过。此次为套件自查，可用于复现结果来核对手册。[工程手册](../engineering-guide.md#怎样选择文档维护方式)
