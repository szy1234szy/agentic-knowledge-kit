# design-gate

## 适用原则
本 Skill 只负责自己的生命周期职责；其他知识类型与审批边界由项目 `AGENTS.md` 和 `docs/knowledge/README.md` 规定。


## 步骤
1. 必须先有 `task-context` 产物。
2. 将每条设计变化映射为受影响模块、接口、数据契约和不变量。
3. 检查是否违反 accepted ADR、Rule 与模块依赖约束；冲突必须明确列出。
4. 重要取舍提出 `ADR proposed`，说明必须满足的约束、可选方案、推荐理由、可验证的预期、兼容与回滚。已有 ADR 时先引用其记录的理由。只有当前实现可以证实的取舍写成当前依据，历史动机待核实。
5. 列出至少一个正向和相关失败/并发/越权测试，说明无法自动验证的部分。
6. 只有已授权的人或仓库治理流程可以批准重大风险与 ADR。
7. 对需要跨阶段追踪的功能，更新已有 Feature 记录或使用 `docs/knowledge/templates/feature-plan.md`。在索引中登记 `kind: feature`、`plan.title` 和适用关系，用 `depends_on` 关联前置功能。通过方案审查后更新状态，保留各项验收判据。

## 输出
设计摘要、沿用的项目能力、保护的不变量清单、变化列表、测试门禁、未决事项、是否允许实施。
