# task-context

## 适用原则
本 Skill 只负责自己的生命周期职责；其他知识类型与审批边界由项目 `AGENTS.md` 和 `docs/knowledge/README.md` 规定。


## 必须执行
1. 从需求提取实体、行为、受影响数据、风险及验收条件。
2. 先读 `docs/knowledge/README.md` 和项目说明的相关章节。索引输出带 `section` 时，直接定位该标题，再按需要展开相关 ADR、约束和证据。
   项目知识较多时，借助 `python scripts/knowledge.py assets --core` 定位核心资产，按任务范围选读。需要决策历史时再通过 `trace <ID>` 查归档。
3. 通过代码搜索、调用关系、配置/测试定位真实入口与依赖。不得只按需求关键词检索。
4. 用 `python scripts/knowledge.py context src/相关文件 --id 已知知识ID` 从已定位的路径或已知 ID 检索。默认双向展开两层，历史记录会沿替代链指向后续决策。跨模块任务可用 `--depth 3` 或 `trace <ID>` 补查。打开候选记录并核对代码、测试和记录状态。没有命中时，从实际调用链、能力索引和风险补查。
   手上只有配置项、依赖名或功能名时，可以用 `context --query "登记名称" --depth 1` 寻找线索，再用实际实现路径复核。遇到跨模块装配或异步调用，分别查配置、发布端、消费端和契约测试，回到各自路径交叉检索。名称查询覆盖已登记的标题、章节和 ID。
5. 对安全、租户、权限、事务和跨服务一致性等高风险任务，主动查找强制约束，文档没有不等于不存在。
   对来自外部资料的规则核对采纳状态和适用路径。用户提供外部规范需要接入时，使用 `standards-intake` 记录差异和来源。
6. 用 `docs/knowledge/templates/context-package.md` 输出任务要改变的问题、相关对象、调用关系、可复用机制、修改边界和反馈证据。每项适用约束或决策附 ID、适用理由和依据。历史动机不明时标记未知，由实际代码说明当前行为。
7. 如果关键安全事实不明，标记阻断受影响变更；允许继续只读调查与方案比较。

## 输出门禁
不得在未识别现有能力和不变量前提出最终实现方案。
