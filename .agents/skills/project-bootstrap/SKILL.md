# project-bootstrap

## 适用原则
本 Skill 只负责自己的生命周期职责；其他知识类型与审批边界由项目 `AGENTS.md` 和 `docs/knowledge/README.md` 规定。


## 执行顺序
1. 检查 Git 根、README、模块/包结构、构建文件、主要配置和测试。
2. 只读定位运行入口、技术栈、模块归属、数据与接口依赖；提供真实路径。
3. 检查已有的团队文档、AGENTS.md、ADR；优先复用而非覆盖。
4. 优先用一份项目说明组织目标、运行主线、模块职责和能力边界，给出候选 Diff，区分已核实事实与未知。只有内容需要独立引用，或维护者、读者、更新节奏明显不同时，才创建独立文档。
5. 对关键能力建立 capability → code/test 链接。相邻主题可以放在同一文档，分别用索引 ID 和 `section` 定位。已有独立 ADR、操作手册或测试证据按需引用。
6. 人工确认后才写入 accepted / verified 状态。
7. 对跨模块调用、部署或质量验证确有需要时，优先引用已有说明。缺失时按知识地图选模板补齐，核实后登记路径、范围和 `asset.last_reviewed`。将影响设计、验收或应急处理的经常使用的资料标为 `core`。
8. 用一条真实使用流程检查资料是否回答「问题 → 对象 → 关系 → 机制 → 边界 → 反馈」。已有概览、架构或决策文档优先补链接。缺少整体导航时，可用 `docs/knowledge/templates/project-understanding.md` 汇总证据入口。

## 禁止
不得根据模块名称推断业务逻辑；不得批量复制整个源码；不得重写已有团队规范；不得将计划标记成当前事实。
